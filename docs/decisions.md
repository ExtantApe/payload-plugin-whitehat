# Decisions

Dated decisions for this repo, newest last.

- 2026-11-09: created from the standard repo starter kit.
- 2026-11-09: built at the owner's decision. MIT; private until the first-public-push audit with the leak check in CI, then public (owner said yes). Never published to npm by a session. Findings about a real site never go in this repo. The engine takes read and write functions from the site, so it is testable without a database.
- 2026-11-10 (0.2.0): **alerts live in the site's database**, in a `whitehat-alerts` collection the plugin adds, never in this repo. Kept by fingerprint (check, role, path); passes resolve, and a finding that never failed isn't stored.
- 2026-11-10: **bulk snooze uses Payload's own bulk Edit** rather than a custom screen (the owner's "select several to snooze in bulk", brief 2026-11-09). An end date within 90 days and a reason are required; a person can change only the snooze. **Retest selected** runs only the suites behind the selection.
- 2026-11-10: **checklist checks take plain answers** (`Ask` returns status, headers, body) or config, so they're testable without a server, and the same code runs read-only against a live site when the owner allows.
- 2026-11-11 (access sweep): only an exact `true` from `access` lets someone see, snooze or retest alerts; any other answer, an error included, is a 403, and the answer is never passed to Payload as access. `access` stays required, with no default.
- 2026-11-13: moved to the ExtantApe GitHub organization and the `@extantape` npm scope at the same version. EXTANT APE owns its reusable tools and licenses them to the platform. The earlier package name is deprecated with a pointer here, and GitHub redirects the old repository address.
- 2026-11-23: **review findings become generic checks.** The plugins lead decided Whitehat should catch on its own the classes of bug that human review found in three plugins. They ship as importable functions with their own broken and fixed fixtures (`docs/review-checks.md`), keep to Whitehat's rules (only finds, severity-ranked, generic, `not-checked` over `pass`), and name no site or plugin. The lint is a heuristic and says so.
- 2026-11-24 (round 13, Head of Tools per D285): **the marker shape is settled.** A 403 `status` as a plain own number, `data` exactly `{ refusal: 'transactions-required' }` as a plain object, `cause` absent or `data`, no `errors`, own keys from a short list. The `TransactionsRequired` class is dropped: plugins throw an `APIError` themselves and import nothing from whitehat. The bare 401, 403 and 404 path uses the same own-key list.
- 2026-11-24 (round 14, Head of Tools review of round 13): **the own-key allow-list checks values.** Text keys are text, statuses are integers that agree, flags are booleans, no getters. On a bare refusal `data` is absent, null or a plain object of plain values. This settles the round 13 shape; the round 12 entry below stands as written, and its mention of the exported class and an open shape is superseded by round 13.
- 2026-11-24 (round 12, owner in Simon's chat, "Switch to marker (Recommended)"): **a refusal is the exported `TransactionsRequired` marker, or a bare 401, 403 or 404, and nothing else.** Whitehat no longer guesses from text: the sentence splitter, driver deny-list, cue words and name list are removed, and everything else is not-checked. The entries below that describe text rules are superseded by this one. The marker's exact shape is open to the Head of Tools.
- 2026-11-23 (third review round): **the checks fail closed on anything ambiguous.** A validation error (400, 422) and any database or transaction error (recognized by `codeName`, `code` and `errorLabels`, also on `cause`) is "not-checked", never a refusal. A host veto must refuse every answer except null and undefined, matching the strict rule other plugins document (`goAhead` lists any other documented go-ahead answer). Back-door probes judge by re-reading the rows, not by the answer. The first 2026-11-23 entry above is the plugins lead's call, recorded from the contributor's decision log. This repo holds no exact words for it, and the entry does not quote or speak for the owner.
- 2026-11-23 (fourth review round): **a database error is never a refusal, whatever the caller passes, and a veto's go-ahead list is closed.** A custom `isRefusal` (or `refusal` pattern) runs only after the database test, which reads the error's fields and, because bulk error entries carry only a message, Mongo's own message words. `goAhead` accepts only `null`, `undefined` and `false`; anything else is a config error, so no single option turns the strict veto check off.
- 2026-11-25 (K768, Head of Tools): **flags left on req.context are a review-finding class.** The same leak was fixed in two plugins this week (OnePedigree and Printify), so Whitehat checks for it at runtime (`runContextLeakCheck`, comparing `req.context` before and after an operation) and in the lint (rule 3, `context-on-shared-req`). Values are never printed, only key names, and an operation that throws is not-checked.
