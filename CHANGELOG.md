# Changelog

## Unreleased

- **Review-finding checks, round 9 (2026-11-23).** Fail-closed fixes. A walk that cannot finish is never a refusal: a driver error hiding more than 6 levels down a `cause` chain under a 403 used to pass, and now reads as not-checked (a cycle is a finished walk and still ends). A Payload `APIError` counts as refusal-shaped only with a 4xx status other than 400 and 422 (those are validation); Payload's default 500 and a missing status do not. More live driver text is caught without driver fields, even under `/transaction|session/`: txnId, "Operation exceeded time limit", "Session ... was ended", and a session id that expired or ended; real plugin refusals such as "has transactions off" with a 403 still pass. The walk also reads `writeErrors`, `writeConcernError`, `errInfo`, `extensions`, `result` and `err` besides `cause`, `originalError`, `errorResponse` and `errors`. A property that throws when read (a `message` getter, say) no longer crashes the check: the result is not-checked. **Behavior change for hosts:** a start-up guard in another plugin that throws a plain Error, or an `APIError` left at 500, now reads as not-checked in the transactions check. Give that guard a 403 (or another 4xx), or pass `refusal` with your own pattern. Tested: the full suite twice (128 tests; 5 new cases and 2 updated ones, all failing on the old code), typecheck, leak check. Not tested: real driver errors on a live MongoDB server (made-up texts and shaped errors only), and a real GraphQL layer.
- **Review-finding checks, refusal rule (2026-11-23).** Fail-closed fixes. The default refusal of the transactions check now needs a refusal-shaped error: a status of 401, 403 or 404, a Forbidden, UnauthorizedError or NotFound name, or a Payload `APIError`, whose message mentions transactions and says no on purpose (needs, requires, must, refuses, cannot, without, off, replica set). A plain Error with only a message is not-checked; pass `refusal` with your own pattern for that case. "has transactions off" with a 403 or an APIError is a refusal again (the cue is the bare word off). Driver text is recognized by structure and wins over any `refusal` pattern, even `/transaction|session/`: txnNumber, lsid, ":: caused by ::", abortTransaction, commitTransaction, withTransaction, ClientSession, timeoutMS, "Read preference in a transaction", committed, aborted, lifetime and ended-session wording, ConflictingOperationInProgress, and server replies with a numeric code and an `errmsg` (codes 72 and 117 included). The fixed character windows are gone, so the full-length TransactionTooOld text is caught without a `codeName`. `originalError` (GraphQL) is walked like `cause`, and an `errors` array of 250,000 entries no longer overflows the stack. Tested: the full suite twice (123 tests; 7 new cases, all failing on the old code), typecheck, leak check. Not tested: real TransactionTooOld, ConflictingOperationInProgress or InvalidOptions errors on a live server (long made-up texts and shaped errors only), and a real GraphQL layer.
- **Review-finding checks, sixth round (2026-11-23).** Fail-closed fixes. The default refusal rule of the transactions check no longer accepts a message for the word "transaction" alone: it must also say no on purpose (needs, requires, must, refuses, cannot, without, off, replica set), so "Transaction failed" is not-checked. Real driver wording is now a database message: "Cannot start transaction ... because a newer transaction ... has already started" (TransactionTooOld, code 225), "No transaction started", "Transaction already in progress" and "Cannot call commitTransaction after calling abortTransaction" (and the reverse). The walk over `cause`, `errorResponse` and `errors` visits each object once, so a self-referential `errors` array no longer grows exponentially, and `errorResponse` is read for `codeName`, `code` and `errorLabels`. The one button label ("Retest selected") has no trailing period, and a test keeps it that way. Tested: the full suite twice (116 tests; 5 of the 7 new cases fail on the old code (the cycle case does not finish there), two guard ordinary refusals and the button label), typecheck, leak check. Not tested: a real TransactionTooOld or double commit on a live server (message text and shaped errors only).
- **Review-finding checks, fifth round (2026-11-23).** Fail-closed fixes. The two lists of Mongo message words are now one, so real driver text such as "Given transaction number ... does not match any in-progress transactions", "Use of expired sessions is not permitted" and "Cannot run 'drop' in a multi-document transaction" is a database message everywhere: under a custom `isRefusal` in all four checks, in bulk entries, and in the transactions check with a catch-all pattern like `/./`. The message test also reads nested `cause`, `errorResponse` and `errors` entries (bounded depth), so a wrapper that only says "Could not save" no longer hides a driver error. The list stays tight: "Members only", "Use a replica set" and "Your session has expired" are still refusals. The `goAhead` test also keeps raw 0 and '' as rejected values. Doc comment for the transactions check corrected. Tested: the full suite twice (109 tests; 5 of the 6 new cases fail on the old code, the sixth guards ordinary refusals), typecheck, leak check. Not tested: a real killed session or expired session on a live server (message text and shaped errors only).
- **Review-finding checks, fourth round (2026-11-23).** Fail-closed fixes. A database or transaction error is never a refusal, whatever `isRefusal` (or the transactions check's `refusal` pattern) the caller passes: the database test runs first, on the error's fields and on Mongo's message words (NoSuchTransaction, WriteConflict, "Transaction ... has been aborted", "operation was interrupted", "session ... was killed", "write conflict", TransientTransactionError), so a bulk `errors` entry that only has a message is covered too; the new `isDatabaseErrorMessage` is exported. A bulk entry that carries Payload's standard "not allowed" text plus one of those phrases is not-checked. `goAhead` on a veto host option accepts only `null`, `undefined` and `false`; anything else throws a config error (a plugin can no longer turn the strict veto check off with `'true'` or `'throw'`). Doc comments for `runHostRuleCheck` match the code. Tested: the full suite twice (103 tests; 10 new cases, 8 of which fail on the old code), typecheck, leak check, and `lintDirectory` on `src`. Not tested: a real killed session on a live server (the bulk and single-document cases use made-up payloads that answer with the driver's message text, plus shaped driver errors), and a real plugin repo's CI.
- **Review-finding checks, third round (2026-11-23).** Fail-closed fixes. Real Mongo transaction errors (NoSuchTransaction, WriteConflict and the like, whose message is plain text) are recognized by `codeName`, `code` and `errorLabels` (including `TransientTransactionError`), also on a nested `cause`, and are never a refusal, whatever custom pattern is passed; `isTransactionError`, `isDatabaseError` and `isValidationError` are exported. A validation error (400, 422, ValidationError) is not a refusal, so a typo in a probe's data is not-checked. A `veto` host option must refuse every answer except null and undefined (new `goAhead` option for a plugin that documents another go-ahead answer), including `{}`, 1, `[]`, 0, an empty string, false, a function and a throw. Back-door probes re-read the rows: an update counts only if a field changed, a delete only if the row is gone, a create only if the row exists, so a silent field lock is a pass, and a typo in `data` is not-checked. Bulk refusals are detected when the entry has a recognized status or name or Payload's standard message; the docs now say so. `lintDirectory` no longer follows symbolic links. Tests close every in-memory Mongo server with cleanup even when destroy throws. Docs: a veto that runs when a holder accepts must be probed at that moment. Tested: the full suite twice (93 tests), typecheck, a real WriteConflict from the in-memory replica set, errors shaped like the driver's, and a run under a private temp folder that left no Mongo folder, process or volume. Not tested: a real plugin repo's CI, a NoSuchTransaction from a live server (shaped objects only), a silent lock on delete (the fixture only locks updates).
- **Review-finding checks, second round (2026-11-23).** Fail-closed fixes: a bulk `errors` entry that isn't a recognized refusal (a TypeError, a database failure) is now not-checked, not a pass; a `veto` host option must refuse on a reason string as well as `true` and a throw; only Mongo's own transaction phrases read as not-checked, so "Use a replica set" in a plugin's own refusal passes; one identity allowed and the other getting a 500 is a finding. Lint: an earlier query must be a Payload call carrying `req` (an Array `.find` no longer hides a find), and spreads of constant objects, in the file or elsewhere in the folder, are followed for `pagination: false`. Smaller: ids under 3 characters are masked, key order no longer counts as a difference, no stray "null" in messages, a function answer does not count as yes (code and CHECKLIST agree), and the lint's pass finding has a relative path. Tested: the full suite (84 tests, each new case failed before the fix) and typecheck. Not tested: a real plugin repo's CI, and the cross-file spread against a real project layout.
- **Review-finding checks (2026-11-23).** Generic checks for the bug classes that human security review found in three Payload plugins, for a plugin repo to run in its own tests or CI: `runResponseDifferenceProbe` (two identities differing in one property must get the same message, status, shape and readable result), `runTransactionCheck` (a plugin must refuse to start or write when the Mongo adapter has transactions off), `runServerBackDoorCheck` (bulk update and delete, `disableTransaction`, `overrideAccess`), `runHostRuleCheck` (`true`, `{}`, null, 0, an empty string, a throw and a narrow where fed into a host rule must not switch a default off) and `lintDirectory` / `lintSource` (a host answer used as any truthy value; a paginated `find` with `req` in a hook). Six new rows in `CHECKLIST.md`; how to run them is in `docs/review-checks.md`.

Review changes (same day): the probes compare values and counts, not only shapes; only a recognized refusal counts as refused, any other error is not checked; bulk probes also run as server code (no user, `overrideAccess`), and a create probe covers `disableTransaction`; the transactions check has a `null-after-start` mode and a tighter default refusal; host-rule fuzz adds 1, `'yes'`, `[]`, false, undefined and a function, plus a veto mode; the lint reads every file and skips a find that follows another query.

Tested: 36 new tests on real Payload 3.92 and in-memory MongoDB, with a made-up fixture plugin that has a broken and a fixed variant for each check (each check is shown to fire and to stay quiet). Not tested: against a real plugin repo's own suite; GraphQL and REST variants of the probes (Local API only); the lint is a text heuristic and will miss code that hides a host hook behind another name.

## 0.2.2 (2026-11-11)

- **Only an exact `true` from `access` lets someone see, snooze or retest alerts (2026-11-11).** Any truthy answer used to count, and the answer went to Payload as the alerts' read and update access as it was, so an object that looked like a query became the read filter. A thrown error answered 500. Now anything but `true`, an error included, is a 403, and the answer is never handed to Payload. There is still no default: `access` stays required. A site whose `access` returns something other than `true` for people it means to let in must return `true`.

Tested: 38 tests (2 new), 5 mutation checks.

## 0.2.1 (never published on its own; released in 0.2.2)

From a security review of 0.2.0. Whitehat's rule is that a check it couldn't make is "not checked", never "passed"; these places broke it.

- **Only a real refusal passes a forbidden write.** Any error used to count as refused, so an allowed write that failed validation (a probe missing a field) passed. Now 401 or 403 pass by default, a write can describe its proper refusal with `refusal`, and anything else is not checked. A refusal that gives something away still fails.
- **The credential check says when it can't see.** If a signed-out visitor already gets a 2xx and the target gives no `secretMarkers`, a bypass would look the same, so each forgery is not checked instead of passed.
- **Alerts for things that are gone resolve.** When a suite runs in full, its open alerts it no longer reports are resolved ("no longer found"), such as a cleaned record or a rebuilt bundle. A suite that reports nothing resolves nothing and is itself not checked. `scanUserContent` always reports a summary, so a clean scan isn't empty. `recordFindings` resolves this way only with `complete: true`.
- **Not checked, not passed:** a canary with no read paths, a canary every viewer may see, an answer that can't be turned into text, and a redirect whose Location can't be read.
- **`allowWriteProbes`** (default off). Suites that try writes are declared `{ run, writes: true }`; the plugin won't start with one while it's off, and `runSuite` records such a suite as not checked without running it.

Tested: 36 tests (8 new; 7 of them fail without these changes, and the eighth checks that partial uploads leave alerts alone, which already held). Not yet run against a real site's suites.

## 0.2.0 (never published on its own; released in 0.2.2)

- **Alerts in the site's database.** The `whitehat` plugin adds a `whitehat-alerts` collection.
  - Findings are kept by fingerprint (check, role, path): a re-run updates an alert rather than adding one, and an alert resolves when its check passes.
  - A suite that fails to run is recorded as "not checked", never as passed.
  - New critical alerts call `onCritical` once.
- **Snooze several at once** with the admin's own bulk Edit. An end date within 90 days and a reason are required, and the snooze holds through later runs until it ends. People can change only the snooze, never what was found, and refusals say why.
- **Retest selected** re-runs only the checks behind the selected alerts (button above the list, or `POST /api/whitehat/retest`).
- **Nine checklist checks:**
  - `checkHeaders`, `checkCookies`, `checkCors`, `checkOpenRedirects`;
  - `checkGraphql` (introspection in production), `checkAdminExposure` (noindex);
  - `checkClientSecrets`, `checkUploads`;
  - `scanUserContent` (scripts in user-written text). The secrets and content scans never copy the matching text.
